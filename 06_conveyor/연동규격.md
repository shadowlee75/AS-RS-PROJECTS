# 컨베이어 연동 계약 v1

## 현재 단계

컨베이어 단독 계산과 데이터 교환용 인터페이스입니다. 실제 다른 장비와 연결된 공통 시계 시뮬레이션은 미구현이며 `capabilities.externalCoSimulation = false`입니다.

`peerType`과 `peerId`는 연결 의도를 기록합니다. 실제 후단 수용 능력은 노드의 `cycle` 값으로 모사합니다. `bufferCapacity: 1`은 노드의 이재 점유 자리 1개를 뜻하며 외부 요청 대기열 길이와 다릅니다.

## 1. 단위와 좌표

- 내부 거리 m, 속도 m/s, 시간 s, 가감속 m/s², 중량 kg.
- X/Z는 평면, Y는 높이. 설정의 `node.height`가 렌더링·포트 위치의 Y가 됩니다.
- `quantity = 1`은 운반물 1개이며 팔레트↔박스 환산은 없습니다.
- 시각 0은 시뮬레이션 시작 시각입니다. 현실 시계의 UTC 시각이 아닙니다.

## 2. 프로젝트

```json
{
  "schemaVersion": "conveyor/project@1",
  "deviceType": "conveyor",
  "moduleVersion": "1.0.0",
  "units": {
    "distance": "m", "speed": "m/s", "acceleration": "m/s2",
    "time": "s", "weight": "kg", "quantity": "handling-unit"
  },
  "config": {}
}
```

전체 예제는 `examples/h.json`을 참조합니다. 모듈 ID는 통합 프로젝트 안에서 고유해야 합니다. 입력 해시는 변경 식별용 FNV-1a이며 보안용 해시는 아닙니다. 배포 파일·소스의 무결성에는 `qa/build-manifest.json`의 SHA-256을 사용합니다.

## 3. 공개 API

브라우저: `CvIO.plugin`, `CvApp.plugin`.

Node.js:

```js
const plugin = require('./src/io').plugin;
const model = require('./src/model');
const config = model.preset('h');
const checked = plugin.validateConfig(config);
const analytical = plugin.calculate(config);
const simulation = plugin.createModel(config);
simulation.advanceTo(600);
const snapshot = simulation.result();
const metrics = plugin.collectMetrics(snapshot);
const ports = plugin.getPorts(config);
const saved = plugin.serialize(config);
const restored = plugin.migrate(saved);
```

| API | 의미 |
|---|---|
| capabilities | 지원 배치·운반물·SI 단위·연동 단계 |
| validateConfig(config) | `{errors, warnings}` 반환 |
| calculate(config) | 경로·자원 요구량·능력·부하·상한 반환 |
| createModel(config) | 단독 결정적 시뮬레이션 생성 |
| advanceTo(t) | 현재 시각 이상, 종료 시각 이하로 진행 |
| result() | 입력·화물 체류 구간·이벤트·표본·누적 수량 반환 |
| collectMetrics(result, t?) | 측정 창의 KPI 반환 |
| getPorts(config) | 입출구 포트 및 연결 대상 반환 |
| serialize / migrate | 현재 프로젝트 규격 저장·검증. 과거 cvcore 변환 기능은 아님 |
| buildReport(result, analytical) | 인쇄용 HTML 문자열 |

`result()`는 실행 중 내부 이력에 대한 읽기용 참조를 포함합니다. 외부 보관에 독립된 복사본이 필요하면 `structuredClone()`을 사용합니다. 이미 예약된 사건을 외부에서 임의 수정하면 안 됩니다. 외부 요청의 실시간 주입이나 외부 수용 콜백은 현재 공개 API에 없습니다.

## 4. 포트와 이벤트

포트 ID: `{moduleId}:{nodeId}`. 자원 ID: `{moduleId}:{resourceId}`.

```json
{
  "portId": "CV-01:OUT1",
  "moduleId": "CV-01",
  "nodeId": "OUT1",
  "direction": "out",
  "resourceId": "CV-01:OUT1",
  "bufferCapacity": 1,
  "transferTimeOwner": "conveyor",
  "transferSeconds": 6,
  "position": {"x": 12, "y": 0.8, "z": -6},
  "peer": {"deviceType": "stacker-crane", "moduleId": "STC-01"},
  "mode": "standalone-cycle-emulation"
}
```

`allowedCargo`에는 설정한 운반물의 규격이 들어갑니다. 대상 경로까지 실제 통과 가능한지는 OD와 컨베이어 전체 검증으로 판단해야 합니다.

연동 내보내기 스키마: `logistics/conveyor-interface@1`. `ports`, `config`, `events`, `metrics`, `configHash`를 포함합니다.

```json
{
  "eventId": "CV-01:OD1-1:completed",
  "type": "HANDOFF_COMPLETE",
  "at": 70,
  "portId": "CV-01:OUT1",
  "externalTaskId": "OD1-1",
  "cargoId": "CV-01:OD1-1",
  "cargoType": "PLT",
  "quantity": 1,
  "flowId": "OD1",
  "ownerModuleId": "CV-01",
  "peerType": "stacker-crane",
  "peerId": "STC-01"
}
```

이 이벤트는 **단독 모형에서 출구 주기가 끝났다는 기록**이며 상대 설비가 실제로 화물을 인수했다는 ACK가 아닙니다. `ownerModuleId`는 이 이벤트를 내보낸 모듈을 뜻하며 연동 후의 화물 소유권 이전을 선언하지 않습니다.

같은 설정·시드·버전으로 만든 기록에서는 이벤트 ID가 안정적입니다. 반복 실험/별도 운전 결과를 함께 적재할 때는 통합 시스템이 고유 `runId`를 추가하여 `(runId, eventId)`로 중복 제거해야 합니다. `externalTaskId`는 CSV 이력 모드에서는 입력 ID, 수요 모드에서는 `{OD ID}-{요청 순번}`입니다.

## 5. 시뮬레이션 사건과 자원

사건 큐는 `(time, sequence)` 이진힙입니다. 같은 시각의 기존 도착·완료 사건을 먼저 순번대로 처리하고 가능한 이재를 예약합니다. 0초 이재 완료가 새로 생성되면 같은 시각에서 다음 처리 단계를 수행합니다.

구간 점유와 후단 예약의 합이 물리 용량을 넘지 않습니다. 이재 시작 시 상류 구간 점유가 이재 노드로 이동하고, 후단에는 예약이 생성됩니다. 이재 완료 시 예약이 실제 구간 점유로 바뀝니다. 노드 공유 자원은 화물 1개만 점유합니다.

시뮬레이터가 추적하는 요청·재고 수지:

```text
initial + generated = completed + wip + backlog
```

예약은 별도 화물로 세지 않습니다. 화물별 `stays`는 edge/node 점유 구간으로, 종료 후에는 중첩 없는 실제 이력입니다. 재생은 이 이력의 소비자입니다.

## 6. 후속 통합 구현 순서

1. 통합 커널의 전역 시계·사건 큐를 주입받는 어댑터를 정의합니다. 개별 엔진을 단순 같은 시각으로 진행하는 것만으로 상호 차단이 구현되지는 않습니다.
2. 요청 ID·화물 ID와 출구별 목적 모듈·포트를 매핑합니다.
3. **READY → RESERVE → TRANSFER → ACK → RELEASE** 인계 상태를 구현합니다.
4. 후단 거절·만재 시 컨베이어 출구를 해제하지 않고 상류에 차단을 전파합니다.
5. 이재시간 소유 모듈 1개를 지정하여 양쪽에서 주기를 중복 더하지 않습니다.
6. 공유 리프트·이재장치를 전역 자원 ID로 1회 생성합니다.
7. 화물 소유권 이전과 취소·타임아웃 복구를 트랜잭션으로 처리합니다.
8. STC / 직선 RGV / LOOP RGV / 셔틀 / AGV·AMR 각각에 가짜 수신자 계약 시험을 추가한 후 실제 모듈에 연결합니다.
9. 장비별 취급량과 최종 시스템 출하량을 구분하고 전체 화물 보존을 검사합니다.

기존 장비 파일의 저장 스키마는 서로 다르므로 현재 컨베이어 JSON을 다른 실행파일에 직접 가져오면 안 됩니다. 통합 시 명시적인 스키마·좌표 변환 어댑터가 필요합니다.
