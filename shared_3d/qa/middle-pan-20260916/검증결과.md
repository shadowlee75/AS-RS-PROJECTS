# 6종 프로그램 · 휠 버튼 화면 이동

수정·검증일: 2026-09-16

## 적용 대상

스태커크레인, 직선 RGV, LOOP RGV, 4-way 셔틀, AGV/AMR, 컨베이어의 소스와 상위 폴더 실행 HTML 6개를 갱신했습니다. 수정 전 파일은 `before/`에 보관했습니다.

## 조작

| 조작 | 동작 |
| --- | --- |
| 휠 버튼(가운데 버튼)을 누른 채 드래그 | 화면을 상하좌우로 이동 |
| 휠 굴리기 | 확대·축소 |
| 좌클릭 드래그 | 회전 |
| 우클릭 드래그 | 화면 이동 |
| 좌클릭 | 셀·차량·장비·구간 선택 |

6개 3D 화면의 OrbitControls 가운데 버튼을 PAN으로 지정하고 화면 평면 방향 이동을 사용합니다. 화면 안내와 README, 스태커크레인 도움말도 갱신했습니다. 휠·우클릭은 선택 동작을 실행하지 않도록 선택 처리를 좌클릭으로 제한했습니다.

AGV/AMR 차량 추적은 차량의 이동량을 카메라에 반영하도록 보완했습니다. 따라서 휠 드래그로 옮긴 상대 시점이 매 프레임 차량 중심으로 되돌아가지 않습니다. 물동량·작업·주행 계산 소스는 변경하지 않았습니다.

## 실제 브라우저 검사

로컬 Edge의 WebGL 화면에서 실제 마우스 가운데·좌·우 버튼과 휠 이벤트를 사용했습니다. 연결된 Browser가 없어 기존 로컬 Playwright 환경을 사용했습니다.

- 6개 프로그램 모두 휠 버튼 드래그 시 카메라와 시선 중심이 같은 거리로 이동했습니다. 시야 방향과 확대 배율을 유지합니다.
- 휠 버튼 드래그·단순 클릭 시 장비 선택과 페이지 자동 스크롤이 발생하지 않았습니다.
- 기존 회전·확대·축소·우클릭 이동·좌클릭 선택이 동작합니다.
- 3D 영역 밖에서 버튼을 놓아도 드래그가 종료됩니다.
- RGV·셔틀·AGV 추적 상태에서 수동 화면 이동을 유지합니다.
- AGV는 재생 시각을 200초로 이동한 뒤에도 선택 차량에 대한 카메라의 상대 이동량을 유지했습니다.
- 카메라 시점 초기화 후에도 휠 버튼 이동이 동작합니다.
- 배포 HTML의 scene 모듈이 수정 소스와 일치합니다. JavaScript 오류·외부 네트워크 요청이 없습니다.

최종 81개 검사 통과. 세부 결과와 배포 파일 SHA-256은 `browser-results.json`, 화면은 `*-pan.png`에 있습니다.

## 기존 배포 검사

- 스태커크레인: 계산 검증 그룹 45개 및 인라인 스크립트 12개 파싱 통과
- 직선 RGV: 계산 36개·장면 7개 검증 및 소스 SHA-256 일치
- LOOP RGV: 계산 검증 그룹 39개·인라인 모듈 13개 및 소스 SHA-256 일치
- 셔틀: 계산 검증 그룹 39개·인라인 모듈 10개 및 소스 SHA-256 일치
- AGV/AMR·컨베이어: 기존 빌드의 라이브러리 무결성 검증 및 갱신한 실제 HTML의 브라우저 검사 통과

## 재검사

프로젝트 상위 폴더에서 설치된 Playwright 경로를 `PAN_PLAYWRIGHT_PATH`로 지정한 뒤 실행합니다.

```powershell
node shared_3d/scripts/middle-pan-check.js
# 특정 프로그램만 확인
node shared_3d/scripts/middle-pan-check.js 05_agv_amr
```

실행 프로그램 자체는 별도 설치 없이 기존처럼 단일 HTML로 엽니다.
