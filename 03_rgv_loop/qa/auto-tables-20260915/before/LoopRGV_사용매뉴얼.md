# Loop RGV 사용 매뉴얼

프로그램 v0.2.1 · 매뉴얼 개정 1.3 · 2026-09-15

v0.2.1은 측정시간 최대 24시간·스테이션 최대 200개를 지원하며 누락 ID를 묶어서 안내합니다. 엑셀 저장·불러오기 기능을 반영했습니다. 기존 계산·3D 기능의 스크린샷은 v0.1.0에서 캡처한 화면이며 사용 방법은 같습니다. 2026-09-14에 적용된 Blender 장비 표시와 장비 확대 기능을 포함합니다.

[프로그램 실행](LoopRGV_실행.html) · [예제 파일](03_rgv_loop/examples) · [검증 결과](03_rgv_loop/qa/검증결과_v0.2.0.md)

## 1. 시작하기

**LoopRGV_실행.html을 Edge 또는 Chrome으로 여세요.** 실행 파일 하나에 계산기와 3D 라이브러리가 포함되어 있어 인터넷, 서버, 별도 설치 없이 사용합니다.

1. 왼쪽 **설정 예시 → 예시 적용**으로 기본 구성을 불러옵니다.
2. 루프 길이·차량 사양을 입력합니다.
3. **설비·스테이션**에서 위치, 상하차시간, 출고 버퍼를 입력합니다.
4. **OD·시간대**에서 출발지→도착지별 요구 물동량을 입력합니다.
5. 왼쪽 아래 **계산 및 설정 적용**을 누릅니다.
6. **3D 시뮬레이션 → 시뮬레이션 재생** 또는 **종료까지 계산**을 누릅니다.
7. **대수별 실험**에서 차량 수를 바꾸어 처리량과 대기를 비교합니다.
8. **프로젝트 저장**으로 입력값을 보관합니다.

입력을 바꾸면 결과가 흐리게 표시되고 재생이 중지됩니다. **계산 및 설정 적용**을 누르면 새 설정을 반영하고 시뮬레이션·반복 실험을 초기화합니다. 보관할 완료 작업 CSV와 실험 JSON은 먼저 내보내세요.

## 3. 루프와 차량 입력

### 루프 형상과 좌표

| 입력 | 의미 |
|---|---|
| 수평 직선 길이 H | 수평 방향의 한쪽 직선 길이 |
| 수직 직선 길이 V | 수직 방향의 한쪽 직선 길이 |
| 코너 반경 R | 네 개의 90° 곡선 중심선 반경 |
| 운행 방향 | 정방향 +s 또는 역방향 −s |
| 거리·속도 단위 | m/mm, m/min/m/s 표시 전환 |

전체 레일 중심선 길이는 **L = 2H + 2V + 2πR**입니다. 외곽 너비·깊이는 각각 H+2R, V+2R입니다.

스테이션의 **s**는 정방향으로 잰 누적거리입니다. 0점은 첫 수평 직선의 시작점이며 화면의 방향 화살표로 확인합니다. 역방향을 선택해도 스테이션의 실제 위치와 s 입력값은 그대로입니다. 방향만 바뀌어 운행거리가 달라집니다. s=L은 0으로 해석합니다.

정방향 거리는 (도착 s−출발 s)를 L로 나눈 나머지, 역방향은 반대로 계산합니다. 같은 위치의 OD는 이동거리 0이며 이재·제어시간만 필요합니다. 이재와 제어도 모두 0인 동일 위치 작업은 입력할 수 없습니다.

### 차량 사양

| 입력 | 의미와 주의점 |
|---|---|
| RGV 대수 | 같은 방향으로 운행하는 본선 차량 수, 1~64대 |
| 차체 길이 | 레일을 따라 점유하는 길이. 3D 차체에도 반영 |
| 최소 차체 간격 | 앞 차량 후미와 뒤 차량 전면 사이의 여유 |
| 1회 최대 적재량 | 작업 하나의 화물 개수. 1~8개 |
| 공차·적재 최대속도 | 상태별 속도 상한 |
| 공차·적재 가속도·감속도 | 각각 별도로 입력하는 일정 가감속 상한 |
| 곡선 제한속도 | 네 코너에 공통 적용 |
| 정차점 저속 접근 | 정차점 앞 저속 구간 길이. 0이면 사용하지 않음 |
| 저속 접근 속도 | 저속 구간에서의 속도 상한 |

단위 전환은 물리량을 유지합니다. 예를 들어 60 m는 60,000 mm, 120 m/min는 2 m/s로 바뀝니다. 프로젝트 JSON은 항상 m·m/s·s·m/s²로 저장합니다.

정적 수용 한계는 **floor(L / (차체 길이 + 최소 간격))**입니다. 이는 정지 차량을 배치할 수 있는 기하학적 한계입니다. 원활하게 운행할 수 있는 차량 수는 시뮬레이션으로 별도 검토하세요. 한계의 30% 초과 알림은 내부 검토 기준입니다.

### 측정시간과 준비운전

**전체 운전시간 = 준비운전(min) + 측정시간(h) × 60**입니다. 기본값은 측정 0.5시간과 준비운전 3분이므로 전체 33분을 계산하고 마지막 30분의 처리량을 집계합니다. 준비운전이 끝나도 차량·작업·버퍼는 이어집니다. 측정시간은 0.05~24시간이며 시간(h) 단위 숫자로 입력합니다. 8시간은 8, 30분은 0.5입니다. 계산 규모와 예상 작업 수 한도는 별도로 적용됩니다.

목표 부하율, 가용도 A, 작업효율 Ew, 도착 변동폭은 0~1 비율로 입력합니다. 예를 들어 80%는 **0.8**, 95%는 **0.95**입니다.

화물 단위 PLT/BOX/TOTE는 취급 수량의 표기입니다. 단위를 바꿔도 화물을 자동 환산하거나 크기·중량을 검증하지 않습니다. 동일 프로젝트에서 유형별 혼합 통계를 나누는 기능은 없습니다.

## 4. 이재시간, 스테이션, 출고 버퍼

### 시간 입력 방식

- **간편·총 시간:** 정위치·인터록·신호 지연이 이미 포함된 총 상차·하차시간을 입력합니다.
- **상세·순수 시간:** 순수 이재시간을 입력하면 공통 정위치·인터록·신호 지연을 더합니다.
- 모드를 전환해도 총 시간은 유지됩니다.
- **배차 제어시간**은 상차 위치에 도착한 후, 상차 전에 작업당 한 번 적용합니다.

예를 들어 정위치 0.5초, 인터록 0.5초, 신호 0초일 때 간편 총 6초와 상세 순수 5초는 같습니다. 간편 총 6초에 공통 지연을 다시 더하지 않습니다.

### 스테이션 표

![스테이션 입력 표](03_rgv_loop/qa/manual-20260915/stations.png)

| 열 | 의미 |
|---|---|
| ID | OD에서 사용하는 식별자. 영문·숫자·_·- 사용, 중복 불가 |
| 이름 | 화면에 표시할 이름 |
| 위치 s | 정방향 누적거리 |
| 상차·하차 | 선택한 이재시간 입력 방식 기준 |
| 버퍼 개 | 목적지 하차 화물을 보관하는 유한 출고 용량 |
| 반출 s/개 | 버퍼에서 외부로 반출하는 간격. 0은 즉시 반출 |

스테이션마다 **상차와 하차가 공유하는 이재부 하나**를 사용합니다. 출고 용량이 부족하면 차량은 목적지에서 화물을 싣고 기다립니다. 이 차량 때문에 뒤 차량들도 정체될 수 있습니다.

버퍼 용량은 최대 배치 수량 이상이어야 합니다. 3개 배치와 반출 간격 10초/개라면 배치 전체가 30초 후에 한 번에 반출됩니다. 초기 출발 작업은 외부 대기열에서 기다리며 이 대기열에는 용량 제한이 없습니다.

**추가 제한속도**에는 시작 s, 끝 s, 속도를 입력합니다. 원점을 가로지르는 구간은 [시작,L]과 [0,끝] 두 행으로 나누세요. 겹치는 제한구간에서는 더 낮은 속도를 적용합니다.

## 5. 요구 물동량과 CSV

### OD·시간대 방식

![출발지와 도착지별 OD 수요 입력](03_rgv_loop/qa/manual-20260915/demand.png)

OD 한 행에 출발 ID, 도착 ID, **화물 개수/h**를 입력합니다. 차량 운행 횟수가 아닙니다.

예: 120 PLT/h, 피크 1.2, 배치 2개라면 기본 생성률은 144 PLT/h, 작업률은 72회/h입니다. 피크는 한 번 적용합니다.

- 시간대 표가 비어 있으면 전체 운전시간에 1배를 적용합니다.
- 시간대가 있으면 지정한 구간에서만 도착하고 공백에서는 작업을 생성하지 않습니다.
- 시작·끝은 준비운전을 포함한 운전 시작 기준 **분**입니다.
- 시간대는 시작 순서로 입력하고 서로 겹치지 않아야 합니다.
- 분석 화면은 최대 시간대 배율을 사용합니다. 시뮬레이션은 시간대별로 적용합니다.
- 일정간격·변동 방식과 포아송 도착을 선택할 수 있습니다. 일정간격 방식도 시작 직후 첫 간격이 지난 시점부터 작업이 도착합니다.

### 작업이력 CSV 방식

**양식 CSV ↓**를 내려받거나 다음 형식을 사용합니다.

~~~csv
time_s,from,to,quantity
0,P1,D1,1
20,P2,D2,1
100,D2,P1,1
~~~

- time_s: 준비운전을 포함한 운전 시작 기준 초
- from, to: 등록된 스테이션 ID
- quantity: 1~최대 적재량 범위의 정수
- 한 행은 한 작업이며 최대 적재량을 넘는 행을 자동 분할하지 않습니다.
- 이력 시각은 전체 운전시간 안에 있어야 합니다.
- 이력 모드에는 피크·시간대 배율·난수를 추가 적용하지 않습니다.
- 분석 요구량은 준비운전 이후 측정구간 이력의 시간당 평균입니다.
- **CSV 불러오기** 후 **계산 및 설정 적용**을 누릅니다.

## 6. 배차와 교통 제어

| 선택 | 동작 |
|---|---|
| 최근접 배차 | 도달 가능한 상차점까지의 거리가 짧은 차량·작업 조합 우선 |
| FIFO 배차 | 가장 먼저 도착한 작업에 도달 거리가 짧은 유휴 차량 배정 |
| 빈차 순환 | 작업 없는 차량도 본선을 순환하며 다음 배차를 받음 |
| 위치 대기 | 유휴 차량이 본선 현재 위치에 정차. 뒤 차량을 막을 수 있음 |
| 간격 추종 | 최소 차체 간격과 제동·추종 여유를 유지하며 주행 |
| 고정 블록 | 한 블록을 한 차량에만 점유·예약하고 전방 블록 확보 후 진입 |

차량은 추월하지 않습니다. 이동 중 새 작업을 받을 때 상차점과 저속 접근 구간까지 충분히 감속할 수 없으면 다음 순환에서 상차합니다.

간격 추종은 **선행차의 현재 후미를 정지 장애물로 보는 보수 제어**입니다. 실제 제어기의 동시 가감속 능력을 그대로 재현하는 모델은 아닙니다.

블록 길이는 차체 길이+간격 이상, 블록 수는 차량 수 이상이어야 합니다. 전면이 다음 블록에 들어가기 전에 예약하고 후미가 빠져나간 후 이전 블록을 해제합니다. 전방 예약까지 포함하므로 한 차량이 여러 블록을 점유·예약할 수 있습니다. 모든 블록을 차량으로 채우면 이동이 불가능해질 수 있습니다.

## 7. 3D 시뮬레이션 조작

![현재 배포 파일의 전체 입체 화면](03_rgv_loop/qa/manual-20260915/simulation.png)

| 조작 | 기능 |
|---|---|
| 재생·일시정지 | 설정한 배속으로 시간 진행·정지 |
| 다음 단계 | 실제 계산 간격 한 단계 진행 |
| 종료까지 계산 | 전체 운전시간을 계산하고 최종 통계 표시 |
| 리셋 | 같은 입력과 시드로 처음부터 시작 |
| 시간 슬라이더 | 특정 시각 탐색. 과거로 이동하면 처음부터 재계산 |
| 정면·평면·전체 입체 | 기본 카메라 시점 |
| 선택 차량·차량 클릭 | 상세 정보를 볼 차량 선택 |
| 선택 차량 확대 | 선택한 차량 주변 확대 |
| Blender 모델 → 장비 확대 | 오른쪽 아래 버튼으로 현재 선택 차량의 상세 형상 확대 |
| 차량 추적 | 카메라가 선택한 차량의 이동을 따라감 |
| 이름·수량 표시 | 차량 ID와 버퍼 수량 표시·숨기기 |
| 마우스 드래그·휠·우클릭 드래그 | 회전·확대축소·평행 이동 |

선택 차량의 ID·상태·위치·속도·작업 정보를 화면 아래에서 확인합니다. 전체 차량의 자세와 위치는 계산 상태에 연결됩니다. 상하차 중에는 화물이 스테이션과 차량 사이로 이동합니다. 곡선과 추가 제한구간, 블록 점유·예약도 레일에 표시됩니다.

차체 폭, 스테이션 형상과 화물 크기는 설명용입니다. 출고 버퍼는 최대 8개 화물을 그리며 실제 수량은 숫자로 표시합니다. 좁은 화면에서 이름이 많으면 숨기고 차량 선택창과 상태표를 사용하세요.

![선택 차량 확대와 설명용 롤러·차체 형상](03_rgv_loop/qa/manual-20260915/vehicle.png)

Blender는 장비 형상 제작에 사용되었으며 실행 PC에는 설치하지 않아도 됩니다. 표시용 장비 모델을 확대해도 입력 사양이나 물동량은 달라지지 않습니다.

WebGL을 사용할 수 없으면 2D 대체 화면에서 같은 계산을 계속합니다. 설정을 다시 적용하면 3D 생성을 다시 시도합니다.

## 8. 결과 읽기

### 물동량 계산

| 지표 | 해석 |
|---|---|
| 무간섭 참고 능력 | 차량 평균 사이클과 실제 스테이션 업무량으로 계산한 참고 능력 |
| 경험 보정 추정 | 차량 능력에 A×Ew×η를 적용하고 스테이션 병목과 비교한 추정 |
| 전체 요구 물동량 | OD 피크·최대 시간대 배율 또는 이력 측정구간 평균 |
| 경험식 최소 대수 | 추정능력×목표 부하율이 요구량 이상인 범위 내 최소 대수 |
| 수요/추정능력 | 100%를 넘으면 추정능력보다 요구량이 큼 |

실제 OD 분석의 공차거리는 이전 도착지와 다음 출발지를 독립적으로 혼합하여 근사합니다. 최근접 배차의 실제 단축·정체는 시뮬레이션에서 확인합니다.

**1랩 개략**은 균일·독립 위치 가정으로 평균 적재 0.5랩+공차 0.5랩을 사용하는 분석 옵션입니다. 시뮬레이션은 이 옵션과 관계없이 실제 OD를 운행합니다.

η 모델은 β 역수식 또는 γ 거듭제곱식을 선택합니다. 설계 가정·실측·벤더 중 근거를 선택하고 설명을 기록하세요. 근거나 보정을 선택하지 않으면 경험 추정과 최소 대수는 **—**입니다. A·Ew·η는 시뮬레이션 관측값에 다시 곱하지 않습니다.

### 시뮬레이션 관측

![완료까지 실행한 시뮬레이션 결과](03_rgv_loop/qa/manual-20260915/simulation-kpis.png)

| 지표 | 해석 |
|---|---|
| 최종 목적지 완료 | 측정구간에 목적지 하차가 끝난 화물 수 / 측정시간 |
| 외부 출하 | 측정구간에 출고 버퍼에서 반출된 화물 수 / 측정시간 |
| 미배차 대기 | 아직 차량을 배정받지 못한 화물 수 |
| P95 최초 배차 대기 | 측정 중 배차된 작업의 도착→최초 배차 시간 95백분위 |
| 미배차 최장 | 현재 미배차 작업 중 가장 오래 기다린 시간 |
| 작업가동 % | 위치 대기·빈차 순환을 제외한 상태시간 비율 |
| 공차거리 % | 측정구간 공차거리 / 전체 이동거리 |
| 최소 실제 차체 간격 | 준비운전을 포함한 운전 전체의 관측 최소 간격 |
| 교착 징후 | 5초 이상 진전이 없고 모든 차량이 정지했으며 해제 예정 이벤트도 없는 상태 |

출고 버퍼가 남으면 **최종 목적지 완료와 외부 출하가 다릅니다.** 두 값을 혼동하지 마세요.

화물 보존은 전체 운전 기준으로 다음과 같이 확인합니다.

**생성 = 외부 출하 + 미배차 대기 + 진행 중 + 출고 버퍼**

준비운전 중의 차량·작업·버퍼 상태는 측정구간으로 이어집니다. 준비운전 중 도착했어도 측정 중 완료되면 완료 처리량에 포함됩니다. 부분 실행 결과는 측정 경과시간으로 환산하므로 초기 값의 변동이 클 수 있습니다.

P95는 이미 배차된 작업을 대상으로 합니다. 과부하 시에는 미배차 수량·최장 대기·대기열 추이를 함께 읽으세요. 작업가동률과 수요/추정능력도 서로 다른 지표입니다.

## 9. 대수별 실험

1. 시험할 OD, 측정시간, 준비운전, 배차와 버퍼 조건을 적용합니다.
2. 최소·최대 대수와 대수 간격을 입력합니다. 간격에 맞지 않아도 최대 대수는 포함합니다.
3. 대수당 1·3·5회 중 반복 수를 선택합니다.
4. **대수별 실험 시작**을 누릅니다.
5. 완료 평균, 95% 신뢰구간, 종료 대기, P95 대기, 최소 간격, 교착 반복 수를 비교합니다.
6. **실험 JSON ↓**로 입력과 반복별 결과를 보관합니다.

![6·8·10대, 대수당 3회 실험의 결과 표](03_rgv_loop/qa/manual-20260915/experiments.png)

각 반복에서 차량 대수들끼리 같은 도착 시드를 사용합니다. 95% 신뢰구간은 반복 평균의 Student t 구간이며 1회는 미산정입니다. 결정적인 작업이력을 반복하면 결과가 같을 수 있습니다.

수요가 낮으면 차량을 늘려도 수요 수준에서 그래프가 평탄해집니다. **최대 처리능력을 시험하려면 충분한 수요를 주고 종료 대기가 남는지 확인하세요.** 시험 범위에 포화가 보이지 않으면 포화 대수를 확정할 수 없습니다. 화면의 범위 내 관측 최대는 단일 반복에서 관측된 최대값입니다.

최대 120회/실험이며 유효 대수·계산 규모를 검사합니다. 취소하면 완료된 반복 결과를 보관합니다. Worker 사용이 불가능한 환경에서는 화면을 갱신하며 분할 계산합니다.

## 10. 저장과 보고서

### 엑셀로 입력조건 저장·불러오기 (v0.2.0)

상단 **엑셀 저장 ↓**는 현재 화면의 입력조건을 .xlsx로 내려받습니다. 아직 계산 및 설정 적용을 누르지 않은 편집값도 검증하여 저장합니다.

1. 프로그램에서 **엑셀 저장 ↓**를 눌러 현재 조건이 들어 있는 양식을 받습니다.
2. Excel에서 **기본조건** 시트의 **입력값** 열과 각 표의 파란색 셀을 수정합니다. 선택 항목은 셀의 목록을 사용합니다.
3. **설비스테이션**, **OD물동량**, **시간대비율** 등의 행을 추가·수정·삭제합니다. 사용하지 않는 표도 시트명과 헤더는 남깁니다.
4. Excel 통합 문서 **.xlsx**로 저장합니다.
5. 프로그램의 **엑셀 불러오기**에서 저장한 파일을 선택합니다. 정상 파일은 즉시 전체 적용되며 시뮬레이션·반복 실험 결과가 초기화됩니다.

| 시트 | 저장·입력하는 내용 |
|---|---|
| 안내 | 양식 식별자, 단위와 편집 방법 |
| 기본조건 | 프로젝트명, 루프·차량·주행·이재·배차·보정계수·시뮬레이션 등 전체 설정 |
| 설비스테이션 | ID, 이름, 위치, 총 상하차시간, 출고 버퍼, 반출 간격 |
| OD물동량 | OD ID, 출발·도착 ID, 피크 적용 전 요구 개수/h |
| 시간대비율 | 시작·끝 분, 수요 비율. 120%=1.2배 |
| 제한속도 | 추가 구간의 시작·끝 위치와 속도 |
| 작업이력 | 도착 초, 출발·도착 ID, 수량 |
| 실험조건 | 최소·최대 대수, 대수 간격, 반복 횟수 |

**엑셀 고정 단위는 거리 m, 속도 m/min, 가감속 m/s², 시간 s입니다.** 기본조건의 화면 거리·속도 단위를 바꿔도 엑셀 숫자의 단위는 유지됩니다. 예를 들어 엑셀 60 m는 화면 거리 단위를 mm로 선택하면 60,000 mm로 표시됩니다.

**스테이션은 항상 총 상하차시간을 입력합니다.** 정위치+인터록+신호가 1초라면 엑셀 총 상차 8초는 상세 화면에서 순수 상차 7초로 표시됩니다. 공통 지연을 두 번 더하지 않습니다.

비율은 Excel에서 **80% 또는 0.8**, 시간대 1.2배는 **120% 또는 1.2**로 입력합니다. 숫자 80과 120을 비율 칸에 그대로 입력하지 마세요. 화물 단위를 바꿔도 수량을 자동 환산하지 않습니다.

엑셀 수식은 불러올 때 계산하지 않습니다. 수식을 사용했다면 **복사 → 값 붙여넣기**로 확정 값으로 바꾸세요. 잘못된 값은 **시트·행 또는 셀 주소**로 안내하며, 이때 기존 화면 입력과 계산 결과는 유지합니다. 시트명·열 제목·기본조건 키·단위를 유지하고, 빈 행은 사용할 수 있습니다. 구형 .xls·매크로 .xlsm·암호화 파일은 지원하지 않습니다.

엑셀은 입력값과 실험 조건을 보관합니다. 완료 작업·실험 결과는 별도로 내보내세요. 저장 위치는 브라우저의 다운로드 설정에 따르며, 기존 엑셀 파일을 직접 덮어쓰지는 않습니다.

![엑셀 저장과 불러오기가 추가된 v0.2.0 화면](03_rgv_loop/qa/excel-20260915/excel-overview.png)


### 엑셀 불러오기 오류 확인

- 측정시간 오류: 입력값과 단위를 확인합니다. 예: 8시간=8, 30분=0.5. 최대 24시간입니다.
- 스테이션 수 오류: 최대 200개입니다. 빈 행은 개수에 포함하지 않습니다.
- 스테이션 ID 연결 오류: OD물동량·작업이력에서 사용한 ID가 설비스테이션 시트에 있어야 합니다. 안내에 표시된 ID의 실제 위치·상하차시간·버퍼를 입력하거나 OD의 ID를 수정하세요. 누락 스테이션의 위치와 사양을 자동으로 생성하지 않습니다.
- 오류가 있으면 이전 입력·계산 결과를 유지합니다. 누락 ID는 중복을 합쳐 목록으로 표시하고 참조 행을 함께 안내합니다.

|---|---|

프로젝트 JSON은 실행 중인 상태와 완료 로그를 저장하지 않습니다. 같은 버전·설정·시드·계산 간격으로 다시 실행하면 재현할 수 있습니다. 예전 Loop 계산기의 JSON이나 다른 설비의 JSON은 직접 호환되지 않습니다.

PDF 보고서는 미리보기 창에서 **PDF 저장 / 인쇄 → PDF로 저장 → A4**를 선택하세요. 브라우저 머리글·바닥글은 끄고 배경 그래픽을 켜면 화면 색상을 유지할 수 있습니다. 상세 재현 자료로 프로젝트 JSON도 함께 보관하세요.

## 11. 포함된 예제와 확인값

아래는 기본 측정시간 0.5시간의 재현 결과입니다. 작업이력 예제는 준비운전 0분이며, 나머지는 준비운전 3분 + 측정 30분으로 전체 33분을 운전합니다. 현장 성능 보증값이 아닙니다.

|---|---:|---:|---|
| 다차량 기본 설계 | 8 | 144 | 실제 OD, 순환과 차량 추종 |

| 증상 | 확인할 사항 |

| 편집 후 재생되지 않음 | 계산 및 설정 적용을 눌렀는지 확인 |

| 차량·블록 입력 오류 | 전체 길이, 차체+간격, 블록 길이와 차량 수 확인 |
| 처리량이 낮고 차가 멈춤 | 출고 버퍼·반출 간격, 본선 위치 대기, 블록 부족 확인 |
| 경험 추정 또는 최소 대수가 — | η와 보정 근거, 수요 0 여부, 목표 달성 범위 확인 |
| 이력 수요가 0 | 이력 시간이 준비운전 제외구간에만 있는지 확인 |
| 시간대 입력 오류 | 시작 순서·겹침·총 운전시간 초과 여부 확인 |
| CSV 오류 | 열 이름, ID, 도착초, 배치 수량, 파일 크기 확인 |
| PDF 창이 안 열림 | 해당 실행 파일의 팝업 차단 설정 확인 |
| 2D 대체 화면이 표시됨 | 브라우저 WebGL·그래픽 가속 사용 가능 여부 확인 |

범위는 **단일 단방향 폐루프, 본선 상하차, 다차량 추종 또는 고정 블록 제어**입니다. 추월·대피선·분기·숏컷·이중루프·배터리·고장·SKU 호환성은 포함하지 않습니다. 실제 기계의 곡선 통과 여유와 측방 간섭은 별도 검토 대상입니다.

교통은 고정 시간격자와 작업 이벤트를 결합해 계산합니다. 각 이벤트는 다음 계산 시각에 반영되고 지연은 누적될 수 있습니다. 중요 조건은 계산 간격을 0.1초에서 0.05초 등으로 줄여 민감도를 확인하세요. 최대 64대·200스테이션·200 OD·30 제한구간·48 시간대·20,000건 이력이며 계산 규모도 제한합니다.



## 13. 기본 예제로 결과 판단하기

### 사례 A: 기본 8대인데 최소 대수는 9대로 표시될 때

기본 수요는 OD 4개 × 30 PLT/h × 피크 1.2 = **144 PLT/h**입니다. 8대의 경험 보정 추정 약 177.1 PLT/h에 목표 부하율 0.8을 적용하면 약 **141.7 PLT/h**로 수요보다 작기 때문에 경험식 최소 대수는 9대로 표시됩니다.

기본 8대 시뮬레이션에서 약 144 PLT/h를 처리하는 결과와 함께 읽으세요. 경험 보정은 설계 여유를 포함한 추정이고 시뮬레이션은 지정한 유한 시간의 실제 모델 관측입니다. 배차 대기, 출고 버퍼, 최소 간격, 대수별 실험을 확인한 뒤 대수를 결정합니다.

### 사례 B: 차량을 16대로 늘려도 처리량이 60 PLT/h일 때

**출고 버퍼 정체** 예시에서는 D1 반출 간격이 60 s/개입니다. 후단 반출 능력은 3600 ÷ 60 = **60 PLT/h**입니다. 버퍼가 차면 적재 차량이 출고 위치에서 기다리며 뒤 차량도 정체됩니다. 차량 수뿐 아니라 반출 주기와 버퍼 조건을 검토해야 합니다.

![출고 버퍼 정체 예시의 운전 종료 화면](03_rgv_loop/qa/manual-20260915/congestion.png)

### 사례 C: 차량을 늘려도 그래프가 평탄할 때

먼저 요구량이 낮아 공급할 작업이 부족한지 확인합니다. 종료 대기가 거의 없고 완료량이 요구량 수준이면 수요에 제한된 시험입니다. 충분한 수요를 입력한 시험에서 대기·간격·버퍼·교착 여부까지 확인해야 최대 능력과 증차 효과를 판단할 수 있습니다.

### 검토 결과를 보관할 때

1. 프로젝트명에 설계안과 개정번호를 기록합니다.
2. 설정 적용 후 종료까지 계산하여 미완료 작업과 대기량을 확인합니다.
3. 같은 수요·측정시간으로 차량 대수를 비교합니다.
4. 프로젝트 JSON, 완료 작업 CSV, 실험 JSON, PDF 보고서를 함께 보관합니다.
5. 사용한 프로그램 버전과 난수 시드, 계산 간격을 기록합니다.

### 컨베이어·스태커 크레인·셔틀·AGV/AMR와 연결할 때

현재 Loop RGV v0.2.0은 단독 프로그램입니다. 연결 대상의 상하차·수용 능력은 스테이션 시간, 출고 버퍼와 반출 간격으로 근사합니다. 다른 장비 프로그램과 공통 시간으로 인계·차단을 주고받는 통합 실행은 제공하지 않습니다.

후속 통합에서는 스테이션 ID와 상대 설비 포트, 동일 화물 ID, 공통 시간, 버퍼 예약, 화물 인수 확인, 상하차시간의 담당 모듈을 매핑해야 합니다. 각 설비의 시간당 처리량을 단순 합산하여 전체 라인 처리량으로 사용하지 않습니다.
