# 싱글딥·더블딥 선택 기능 검증

- 버전: STC Studio v0.3.1 / 2026-09-17
- 실행 파일: 상위 폴더 `스태커크레인_실행.html`
- 변경 전 백업: `01_stacker_crane/backups/20260917_double_deep`

## 적용 내용

- 랙 설정의 **화물 보관 깊이**에서 싱글딥/더블딥 선택.
- 기본값과 기존 프로젝트는 싱글딥. 더블딥은 각 번지·단·면에 D1/D2를 생성하고 저장 수량을 2배로 계산.
- 앞열·뒷열의 실제 포크 편도거리로 SC/DC 및 FEM 결합 계산. 뒷열 입력은 통로 중심부터의 총 거리이며 빈칸은 앞열의 2배. 뒷열은 앞열보다 커야 함.
- 3D 랙·셀 선택, 운동 그래프의 깊이 선택, JSON 저장/불러오기, CSV 주소, MD/PDF 및 도움말·사용 매뉴얼 연결.
- 시뮬레이션은 뒷열 우선 입고, 앞열이 비어 있을 때만 뒷열 접근. 같은 번지·단·면의 앞열/뒷열을 DC 입출고로 예약하지 않음.

## 검증

| 검증 | 결과 |
| --- | --- |
| `npm test` | 83개 통과: 기존 74개 + 깊이 관련 9개 |
| `npm run build` | 오프라인 실행 HTML 생성 |
| `npm run shipcheck` | 배포 HTML에서 추출한 모듈의 45개 검증 그룹 통과, 12개 스크립트 구문 정상 |
| `node scripts/browser-depth-check.js` | Edge 로컬 검증 22개 통과, JavaScript 오류 및 외부 네트워크 요청 0건 |
| 화면 확인 | 선택 항목, 앞열/뒷열 3D, 운동 그래프, 보고서 표 너비, 매뉴얼 확인 |

깊이 테스트는 보관 수량/좌표/주소, 이전 JSON 호환, 범위 검증, 포크 시간의 독립 계산, CASE 1~6과 실제/이론 대표점, 접근 가능한 서로 다른 위치의 DC 전수 계산, 모든 운전 모드의 이벤트별 접근 조건·재고·작업 보존, 단방향 입고 만재/출고 전량 배출, 복수 STC 재생 일치성을 확인합니다.

브라우저 검증은 연결된 Browser 런타임이 빈 목록을 반환하여 기존 프로젝트 방식의 로컬 Playwright/Edge로 실행했습니다. Playwright는 프로젝트 외부 임시 폴더에 설치했습니다. 실행 시 `STC_PLAYWRIGHT_PATH` 또는 `%TEMP%/stc-depth-browser/node_modules/playwright`를 사용합니다.

## 계산 범위

분석은 앞열·뒷열 50:50 및 접근 가능 조건의 평균입니다. FEM 결합은 설계 확장입니다. 시뮬레이션 FIFO는 접근 가능한 재고에 적용합니다. SKU 지정 출고와 차단 화물 재배치 작업은 포함하지 않습니다. 저장 용량 증가가 동일 비율의 시간당 물동량 증가를 뜻하지 않습니다.
