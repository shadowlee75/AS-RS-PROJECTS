# 스태커크레인 물동량 계산·시뮬레이터 v0.3.1

개발계획서 v1.2를 바탕으로 계산, 재고 기반 시뮬레이션, 3축 가감속 그래프를 연결한 독립 프로그램입니다. 기존 개발계획서와 별도 폴더의 v1.0 계산기는 수정하지 않았습니다.

## v0.3.1 추가 기능: 싱글딥·더블딥 선택

1. 왼쪽 **랙 & 스테이션 → 화물 보관 깊이**에서 **싱글딥** 또는 **더블딥**을 선택합니다.
2. **주행·승강·포크 → 포크 편도 스트로크 · 앞열**과 **뒷열 포크 편도 스트로크**를 확인합니다. 각각 통로 중심부터 화물 중심까지의 **총 편도거리(m)**입니다. 뒷열은 앞열보다 커야 하며 빈칸은 앞열의 2배를 설계 가정으로 적용합니다.
3. **계산 및 설정 적용**을 누릅니다. 저장 셀 수 = 번지 × 단 × 보관면 × 깊이(싱글 1 / 더블 2) × STC 수입니다. 기본 랙은 싱글딥 600셀, 더블딥 1,200셀/STC입니다. 저장 용량이 2배여도 시간당 처리량이 2배가 되는 것은 아닙니다.
4. **3D 시뮬레이션 → 깊이**, **운동 그래프 → 입고 깊이 / 출고 깊이**에서 D1(앞열), D2(뒷열)를 선택합니다. 더블딥 주소에는 `-D1` 또는 `-D2`가 붙습니다. 프로젝트 JSON, 완료 작업 CSV, 계산서 MD, PDF 보고서에도 반영됩니다.

보관 깊이는 보관면 수 및 SC/DC 운전 모드와 별개입니다. 기존 프로젝트는 싱글딥으로 불러오며, 싱글딥에서는 뒷열 입력을 사용하지 않습니다.

**계산 가정:** 분석은 앞열·뒷열을 50:50으로 선택한 포크 이재시간 평균입니다. FEM CASE와의 결합은 설계 확장으로 표시합니다. DC의 입고·출고는 서로 다른 번지·단·면을 사용합니다. 시뮬레이션은 뒷열 우선 입고, 앞열이 비어 있을 때만 뒷열 접근, 접근 가능한 재고 내 FIFO를 적용합니다. SKU 지정 출고 및 앞열 화물 재배치 작업은 포함하지 않습니다.

## 실행

상위 폴더의 **`스태커크레인_실행.html`을 Edge 또는 Chrome으로 여세요.** 설치, 서버, 인터넷 연결이 필요 없습니다. 이 HTML 한 파일만 복사해도 실행됩니다. Three.js r128과 OrbitControls가 파일 안에 포함되어 있습니다.

1. 왼쪽에서 랙, 주행·승강·포크 사양, 요구량을 입력합니다.
2. **계산 및 설정 적용**을 누릅니다. 숫자는 예시 사양입니다.
3. 보정 처리량·필요 대수까지 보려면 **분석 보정계수**를 펼쳐 A, Fₜ, E𝑤 및 근거를 선택합니다. 기본값은 비어 있습니다. `가정 예시 적용` 또는 `이상 조건 1.0`을 선택한 뒤 다시 적용할 수 있습니다.
4. **3D 시뮬레이션**에서 재생, 일시정지, 다음 이벤트, 종료까지 계산, 리셋, 시각 탐색을 사용합니다. 배속은 1~1000배입니다.
5. **운동 그래프**에서 STC, 입고·출고 각각의 번지/단/면과 SC/DC를 선택합니다. FEM 계산 적용 후에는 경로를 FEM 대표점으로 전환할 수 있습니다. 주행·승강·포크 각각의 속도/가속도 또는 위치/속도 그래프를 볼 수 있습니다. 재생·슬라이더·그래프 위 포인터로 동일 시각을 확인합니다.
6. **반복 실험**에서 기본 3가지 운전 모드를 5~30회씩 비교합니다. 지정 비율 모드에서는 현재 비율도 함께 비교합니다.

입력 변경 후에는 이전 결과가 흐리게 표시되며 재생과 결과 내보내기를 차단합니다. `계산 및 설정 적용`은 시뮬레이션과 반복 실험 결과를 초기화합니다. 원래 입력으로 돌아가려면 미리 프로젝트 JSON을 저장하세요.

## v0.2.6 항목별 ? 도움말

상단 메뉴, 왼쪽 설정의 모든 입력 항목과 접기 메뉴, 분석 탭, 결과 제목, 시뮬레이션·운동 그래프 조작, 반복 실험, PDF 보고서 옵션에 **?**를 추가했습니다. 기본 화면 구성 기준 147곳입니다. STC별 포트 표에는 각 열의 제목 옆에 도움말이 있으며 표 갱신 후에도 유지됩니다.

- **마우스 올리기:** 해당 항목의 의미, 단위, 입력 기준과 예시를 표시합니다. 설명 안으로 마우스를 옮겨 계속 읽을 수 있습니다.
- **클릭 또는 터치:** 설명을 고정합니다. 다른 ?를 클릭하면 그 항목의 설명으로 바뀝니다.
- **닫기:** 같은 ? 재클릭, 설명의 ×, 바깥 클릭 또는 Esc를 사용합니다.
- **키보드:** Tab으로 ?에 이동하면 설명이 열립니다. Enter/Space로 고정하고 Esc로 닫으면 원래 ?로 포커스가 돌아옵니다.

랙 외부 음수 포트, 개별 포트 빈칸과 0의 차이, P1·P2 실제 화물 중심, m/min 및 m/s², 캐리지 UP/DOWN 110 mm, 보정계수의 근거, 대기 통계와 PDF 제출 순서를 설명합니다. 도움말 클릭은 메뉴 실행·체크박스 변경·설정 적용을 일으키지 않습니다. 입력을 수정하고 아직 적용하지 않은 상태에서도 도움말을 사용할 수 있습니다.

도움말은 인터넷 연결 없이 동작하고 계산서/PDF에 출력되지 않습니다. 기존 실행 창은 새로고침하거나 HTML을 다시 열어 사용하세요. 검증: [qa/검증결과_v0.2.6.md](qa/검증결과_v0.2.6.md), 재실행: `node scripts/browser-help-check.js`.

## v0.2.5 제출용 PDF 보고서

1. **계산 및 설정 적용**으로 현재 입력을 계산합니다. 시뮬레이션 결과를 제출하려면 먼저 원하는 구간까지 실행합니다.
2. 화면 오른쪽 위 **PDF 보고서**를 누릅니다.
3. **문서번호·제출처·작성자·검토자**를 필요에 따라 입력합니다. 선택 경로 배치도/가감속 그래프와 현재 시뮬레이션 결과의 포함 여부를 선택합니다.
4. **보고서 미리보기**를 누르면 별도 창에 A4 보고서가 열립니다.
5. 미리보기의 **PDF 저장 / 인쇄**를 누르고 인쇄 대상을 **PDF로 저장**, 용지를 **A4**로 선택한 뒤 저장합니다. 브라우저 기본 머리글·바닥글은 끄세요. 보고서 자체의 페이지 번호와 바닥글이 포함됩니다.

보고서는 프로젝트·문서 정보, 요구량/이론 능력/보정 능력/필요 대수, 랙·동작·운영 입력, STC별 실제 포트와 SC/DC 결과, FEM 적용 좌표/참조 좌표, 선택 경로 배치도와 3축 가감속 그래프, 시뮬레이션 결과, 보정계수 민감도와 계산 조건을 담습니다. 그래프는 운동 그래프 탭에 적용된 STC와 경로를 사용하며 보고서에 해당 주소와 경로 종류를 표시합니다.

입력을 변경하고 적용하지 않은 상태에서는 보고서 생성을 차단합니다. PDF 보고서를 여는 시점에 재생을 일시정지하여 현재 시점 결과를 담습니다. 시뮬레이션 상태는 **미실행 / 준비운전 중 / 진행 중-부분 결과 / 완료 / 보고서에서 제외**로 구분합니다. 보정계수와 근거가 없으면 능력·필요 대수는 미산정, 판정은 보류로 표시합니다. 문서 정보는 현재 앱 창에서 유지되며 프로젝트 JSON의 설비 사양에는 저장되지 않습니다.

PDF는 브라우저의 인쇄 기능으로 저장하며 인터넷이나 PDF 서버가 필요 없습니다. 기존 Markdown 계산서는 **계산서 MD ↓**로 계속 저장할 수 있습니다. 검증: [qa/검증결과_v0.2.5.md](qa/검증결과_v0.2.5.md).

## v0.2.4 캐리지 110 mm 상하차

사용자 지정 순서에 따라 **상차: 포크 OUT → 캐리지 UP 110 mm → 포크 IN**, **하차: 포크 OUT → 캐리지 DOWN 110 mm → 포크 IN**을 적용합니다. IN 상차, 랙 입고 하차, 랙 출고 상차, OUT 하차에 공통 적용하며 모든 STC가 각각 재생합니다.

왼쪽 **주행·승강·포크 → 캐리지 이재 승하강량**은 기본 **110 mm**입니다. 입력과 계산서는 mm, JSON의 `transferLift`는 m(0.11)로 저장합니다. 입력 Y와 P1·P2는 놓인 화물의 중심을 유지합니다. 상차 후 적재 이동은 그 중심보다 110 mm 높고, 하차하면 원래 중심으로 돌아옵니다. 3D 화물은 상승 중 포크를 따라 움직이며 하차 후에는 랙에 남고 포크만 인입합니다. 입고 예약 셀에는 화물이 미리 나타나지 않습니다.

승하강 중 포크는 완전 신장 상태로 정지합니다. 캐리지 이재 시간은 기존 승강 Y 속도·가감속과 적재 비율로 계산하고, 승강 그래프에 UP/DOWN 펄스와 가감속을 표시합니다. 별도 이재 저속은 현재 입력하지 않습니다. 기본 사양(vy=60 m/min, ay=dy=0.5 m/s², 적재 비율=1)에서는 110 mm 운동이 약 **0.9381초/이재**로 SC에 2회, DC에 4회 포함됩니다. 양 끝의 적재 높이가 같은 양만큼 올라가므로 적재 이동거리는 유지됩니다.

**이재 후 안착 대기**는 승하강 완료 후 포크 IN 전의 추가 정지 시간입니다. 기존 ‘승하강·안착’ 입력에 승하강 시간이 포함되어 있었다면 안착 대기만 남겨 입력하세요. `transferLift`가 없는 이전 프로젝트에도 110 mm를 적용하므로 사이클타임이 달라집니다. 승하강량 0 mm는 이전 지연만 사용하던 운동 모델의 비교용입니다. 재고와 작업 완료 수량은 기존과 같이 각 포크 IN 완료 시 집계합니다.

검증: [qa/검증결과_v0.2.4.md](qa/검증결과_v0.2.4.md), 재실행: `node scripts/browser-transfer-check.js`.

## v0.2.3 외부 포트와 실제 화물 중심

IN/OUT의 X는 **−500~500 m**, Y는 **−100~100 m** 범위에서 랙 외부 좌표를 허용합니다. 랙 왼쪽 끝은 X=0, 오른쪽 끝은 X=랙 길이입니다. 길이 33.9 m인 랙에서 X=−3은 왼쪽 외부 3 m, X=38은 오른쪽 외부 4.1 m입니다. 기본 좌표와 STC별 표 모두 동일하게 적용되며, 포트 Z는 포크 스트로크 이내입니다.

랙 길이·번지수로 정해지는 화물 중심을 유지하면서 포트까지의 실제 운동시간을 계산합니다. 2D 표시 범위, 3D 레일·승강 범위·카메라도 포트를 포함하도록 확장됩니다. 바깥 포트를 입력하기 위해 랙 길이를 늘릴 필요가 없습니다. 화물은 각 셀의 중앙에 배치하며, 시각화 셀 경계는 중심 높이 ± 단간격/2입니다.

**P1·P2 적용 위치 → 실제 화물 중심**이 기본입니다. CASE 참조점에서 가까운 실제 셀을 선택하고 그 셀의 XYZ를 물동량 계산·표·배치도·3D·운동 그래프에 공통 적용합니다. 등거리이면 작은 셀 ID를 우선하며, P1/P2가 겹치면 P2는 다른 셀 중 가장 가까운 중심을 선택합니다. 전체 셀이 하나이면 DC는 사용할 수 없습니다.

CASE 포트 조건과 다른 배치도 실제 화물 중심 모드로 계산할 수 있습니다. 이때 CASE의 표준 참조 배치로 셀을 선정하고 실제 입력 포트까지의 경로를 계산하는 **설계 확장**으로 표시합니다. 두 포트가 랙 오른쪽에 있으면 참조 배치를 좌우 반전합니다. 적용 좌표와 이론 비교 좌표, 셀 선정에 사용한 참조 포트를 계산서에 기록합니다. **FEM 이론 좌표 · 비교**를 선택하면 원래 CASE 포트 조건과 연속 좌표를 사용합니다.

이전 JSON에 `pointMode`가 없으면 실제 화물 중심 모드를 적용합니다. 이전 FEM 수치를 재현하려면 이론 좌표 비교를 선택하세요. **CASE 포트 배치 적용** 버튼은 입력 포트를 참조 배치로 변경하므로 외부 포트를 유지하려면 CASE 선택 후 바로 계산을 적용합니다.

예시: `examples/07_외부포트_P1P2_화물중심.json` (설명용 가정값, 첨부 도면의 확정 사양 아님). 검증: `qa/검증결과_v0.2.3.md`.

## v0.2.2 1단 높이와 분당 속도

**랙 & 스테이션 → 1단 랙 이재 높이**에 바닥 기준 Y(m)를 입력합니다. **단간격**은 각 단의 이재 높이 사이 거리입니다. 예를 들어 1단 0.5 m, 단간격 2 m이면 1~4단은 0.5 / 2.5 / 4.5 / 6.5 m입니다. 최상단 높이 `1단 높이 + (단수−1)×단간격`이 랙 높이 H를 초과하면 적용을 차단합니다.

단간격을 비우면 H/단수, 1단 높이를 비우면 단간격/2를 사용합니다. 두 칸이 없는 이전 JSON은 자동값으로 불러와 기존 셀 위치를 유지합니다. 단별 높이 표, 2D/3D 셀과 단 번호, 실제 셀 운동 그래프, 전체 셀 평균 계산과 모든 STC의 운영 시뮬레이션에 함께 적용합니다. v0.2.3의 기본 P1·P2도 이 실제 셀 중심을 사용합니다. 비교용 이론 대표점은 H 기준입니다.

주행·승강·포크의 기본 속도 단위는 **m/min**입니다. 예시 속도는 각각 **180 / 60 / 36 m/min**이며, 입력·그래프 눈금·도달속도 표·실시간 표시·계산서가 같은 단위를 사용합니다. 가감속은 **m/s²**입니다. 기존 프로젝트의 표시 단위는 저장된 선택을 유지하고, 선택기를 바꾸면 물리적 속도를 유지하면서 환산합니다. JSON은 표시 단위와 무관하게 속도를 m/s로 저장합니다.

설정 예시: `examples/06_1단높이_단간격.json`. 검증: `qa/검증결과_v0.2.2.md`.

## v0.2.1 속도 입력 안내 수정

속도 오류 문구에 선택한 단위와 현재 입력값을 표시합니다. 주행 허용 범위는 **0.001~20 m/s**, 같은 범위를 분당 단위로 표시하면 **0.06~1200 m/min**입니다. 입력칸 아래에는 허용 범위와 다른 단위의 환산값을 함께 보여주고, 오류가 있는 입력칸을 강조합니다.

예를 들어 사양이 **180 m/min**이면 단위를 m/min으로 먼저 선택한 뒤 180을 입력하거나, m/s 상태에서 3을 입력하세요. 단위 선택을 바꾸면 기존 세 축 속도가 환산되므로, m/s 상태에서 180을 입력한 후 단위만 바꾸면 10800 m/min이 됩니다. 이 경우 원하는 값 180을 다시 입력해야 합니다. 가속도와 감속도의 단위는 m/s²입니다.

프로젝트 JSON 내부 속도는 표시 단위와 무관하게 항상 m/s로 저장됩니다. 자세한 검증은 `qa/검증결과_v0.2.1.md`를 참조하세요.

## 입력과 집계 원칙

- 내부 단위: m, m/s, m/s², s. 속도 입력·표시는 기본 m/min이며 m/s ↔ m/min 변환을 지원합니다. 표시 단위를 바꾸어도 사양은 같습니다.
- 셀 위치: `x=(Bay−0.5)×길이/Bay수`, `y=1단 높이+(Level−1)×단간격`. 자동값에서는 이전 식 `y=(Level−0.5)×높이/Level수`와 같습니다. 한 셀은 화물 1개를 보관합니다.
- 주행/승강: `max(tx,ty)`로 동시 이동합니다. 실제 이동이 있을 때만 정위치 시간을 한 번 더합니다. 적재 비율은 속도·가속도·감속도에 함께 적용됩니다.
- 포크 이재 1회: 편도 스트로크 운동 2회 + 캐리지 이재 승하강 운동 1회 + 안착 대기. SC에 2회, DC에 4회 사용합니다. 캐리지 이재는 포크 이재 시간에 포함되며 별도의 총 이재시간을 중복 가산하지 않습니다.
- 제어 지연은 사이클당 한 번입니다. creep와 jerk 제한은 이 버전의 운동식에 포함하지 않습니다.
- 전체 셀 평균 모드 SC: 전체 물리 셀을 균일하게 선택하는 각 포트 복귀 사이클의 평균입니다. DC: 서로 다른 두 셀의 평균이며 60,000쌍 이하는 전수, 그 이상은 30,000쌍 표본(고정 시드 9851)입니다. 평균 이동시간의 표준오차를 출력합니다.
- DC 비율은 **전체 사이클 중 DC 비율**입니다. 분석에서는 수요 구성이 허용하는 최대 `min(입고,출고)/max(입고,출고)`를 사용합니다. 실제 도착/재고와 배차에서 성립하는 DC 비율은 DES 결과에서 달라질 수 있습니다.
- 총 취급량은 입고+출고입니다. DC 1회가 출고 2건을 뜻하지 않습니다.
- SC-return은 I/O로 복귀합니다. SC-stay는 마지막 위치에 대기합니다. DC는 입고와 출고를 동시에 예약하고, 한쪽이 없을 때 SC-stay로 실행합니다. 동일 시각의 도착을 모두 반영한 뒤 배차합니다.
- 전체 수요를 독립 통로에 균등 배분한다고 가정합니다. **DES는 모든 통로를 각각 실행**하고 각 통로에 `전체 평균 수요×피크계수/통로 수`를 투입합니다. 전체 결과는 각 통로의 실제 관측량을 합산합니다.
- 필요 통로 수는 `ceil(전체 피크 수요 / (입력 STC 중 최저 보정능력×목표 부하율))`입니다. 공통 상하류 병목이 없는 독립 통로의 조건부 분석입니다.
- A, Fₜ, E𝑤는 분석 능력에 한 번만 적용합니다. DES는 고장 없는 조건이며 이 계수로 다시 차감하지 않습니다. 1.0인 계수는 해당 손실을 제외하는 이상 조건입니다.

전체 셀 수 120,000개, STC 100대, 전체 예상 작업 100,000건 및 통로별 30,000건을 한도로 검증합니다. 한도를 초과하면 입력 오류를 표시하며, 장면의 STC나 셀 수를 자동으로 줄이지 않습니다.\n\n## 시뮬레이션 경계

입고 버퍼가 차면 추가 입고는 외부 backlog로 대기합니다. 랙에 빈 셀이 없으면 입고할 수 없고, 재고가 없으면 출고할 수 없습니다. 출고 버퍼가 찼을 때 크레인은 I/O 하차 전에 화물을 들고 대기하며, 외부 반출로 자리가 생기면 작업을 재개합니다. 반출 간격 0은 즉시 반출입니다.

입고 완료는 랙 하차 완료, 출고 취급 완료는 I/O 하차 완료입니다. 외부 출하는 출고 버퍼에서 실제 반출된 수량입니다. 효과 시점은 각 포크 이재의 완료 시점입니다. 초기 재고 보유 시각은 결정적인 순서로 지정하며, 실제 SKU·화물 나이는 모델링하지 않습니다.

총 운전시간 = 준비운전 + 측정시간입니다. 준비운전의 상태와 재고는 유지하면서 측정 통계만 제외합니다. 처리량은 측정구간에 완료된 작업 수/측정시간이므로 준비운전에서 넘어온 작업도 포함합니다. 대기 통계는 **측정구간에 배차된 작업의 도착→배차 시간**이며 DC의 두 작업 모두 페어 배차 시각을 서비스 시작으로 정의합니다. 종료 시 미배차 작업은 이 통계에서 제외되어 별도로 표시됩니다.

재고 보존식:

`초기 랙 재고 + 누적 입고 완료 − 누적 출고 취급 완료 = 현재 랙 재고 + 크레인 위 출고 화물`

작업 보존식:

`누적 생성 = 누적 완료 + 대기 + 진행 중`

이벤트는 `(시각, 생성 순서)`로 정렬합니다. 도착/초기재고/저장위치/출고위치에 별도 난수 스트림을 사용하며 모형 내부에서 `Math.random`을 사용하지 않습니다. 화면 프레임은 이벤트 통계의 적분 경계를 바꾸지 않습니다. 반복 r의 시드는 `(기본 시드+r) mod 2³²`입니다.


브라우저 자동 검증은 개발용 Playwright와 Edge를 사용합니다. 연결된 Browser가 없던 환경에서 독립 임시 디렉터리의 Playwright 1.55.1로 확인했으며, 배포 HTML에는 포함되지 않습니다. `STC_PLAYWRIGHT_PATH`에 Playwright 모듈 경로를 지정하거나 `%TEMP%/stc-browser-check/node_modules/playwright`를 사용합니다.

`scripts/capture-legacy.js`는 기존 HTML을 읽어 비교 데이터를 다시 생성하는 개발 도구입니다. 일반 빌드/시험에 기존 HTML 원본이 필요하지 않도록 캡처된 JSON을 포함합니다. v0.2 검증 결과는 `qa/검증결과_v0.2.md`를 참조하세요.

외부 코드: [Three.js r128](https://github.com/mrdoob/three.js/tree/r128), [MIT 라이선스](https://github.com/mrdoob/three.js/blob/r128/LICENSE). 원본 URL과 각 파일 SHA-256은 `vendor/manifest.json`에 기록했습니다.


## 3D 화면 이동 · 2026-09-16

3D 화면 안에서 **마우스 휠 버튼(가운데 버튼)을 누른 채 드래그**하면 화면이 상하좌우로 이동합니다. 휠을 굴리면 확대·축소하고, 좌클릭 드래그는 회전, 우클릭 드래그는 이동입니다. 장비 선택은 좌클릭으로 합니다. 변경된 실행 HTML을 새로 열면 적용됩니다.
