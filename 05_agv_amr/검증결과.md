## 운영·재생 검사

- 요청 발생 = 완료 + 활성 미완료. 완료 시각·배정 시각·픽업 인계의 순서를 검사했습니다.
- 차량별 상태시간 합과 시계열의 틈·중복을 검사했습니다.
- 시작 에너지 − 소비 + 순충전 = 종료 에너지, SOC 범위를 검사했습니다.
- 동시 이동 경로와 정지 차량의 원형 외곽, 스테이션/충전기 단일 차량 점유, 유한 화물 버퍼를 검사했습니다.
- 0.1 s / 0.05 s의 별도 위치 샘플에서도 예제 차량 간 외곽 중첩이 없었습니다.
- 후공정 속도를 낮추면 버퍼가 차고 로봇의 하역 대기로 전파됩니다.
- 폐쇄 구간은 신규 경로 진입에서 제외되며, 고정 경로와 동적 우회 예제의 완료량이 달라집니다.
- 충전 대기·도달 에너지 부족·장시간 SOC 고갈이 결과에 기록됩니다.
- 같은 시드의 요청은 대수/정책과 독립적으로 생성되고, 같은 입력은 같은 사건·KPI를 재현합니다.
- 3D 재생·배속·2D 전환·이전 시각 이동은 계산 로그와 전체 KPI를 바꾸지 않습니다.
- 변경된 조건을 계산 중일 때 이전 운전 결과와 새 입력을 섞어 보고서로 내보내지 못하도록 검사했습니다.

## 입출력·UI 검사

- HTML 더블클릭과 Worker 계산, Three.js 장면 표시.
- 재생·일시정지·다음 사건·양방향 seek·카메라·차량 선택·추적.
- 3D PNG 캡처, 프로젝트 JSON 왕복, XLSX 비압축/Deflate 압축 파일 왕복.
- 잘못된 스키마·하중·단위·헤더·중복·비연결 입력 거부와 기존 설정 보존.
- 2D 좌표 편집과 포인터 드래그의 250 mm 격자 이동.
- 대수 비교, 보고서·전체 작업·재생 기록 내보내기.
- 0 수요의 필요 대수 0 및 P95 계산 불가 표시.
- 작은 화면의 수평 페이지 넘침 방지와 WebGL 없는 환경의 2D 대체.

## 계산 시간 관측

Node v24.18.1 / Windows의 계산 전용 측정입니다. 각 사례는 차량 4대·노드 40개·경로 41개입니다. 계획서의 50대·500노드·1,000경로 기준 성능 검수와는 다릅니다.
